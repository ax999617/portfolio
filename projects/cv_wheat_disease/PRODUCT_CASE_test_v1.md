# 小麦病害风险预警 Demo：产品案例 - test v1

## 产品定位

这是一个用于展示“上传图片 - 返回演示分类 - 风险分级 - 知识解释 - 决策提示”的应用原型。当前真实模型未接入，因此产品价值只落在流程、接口、错误处理与风险沟通，不落在诊断精度。

## 用户与任务

- 演示者：需要在竞赛或作品集中说明端到端产品流程。
- 前端/后端协作者：需要稳定的输入、响应与错误合同。
- 农业场景审阅者：需要一眼区分演示结果、人工复核和实验室检测。

核心任务：用户上传一张图片后，系统返回统一结构，并明确该结果是否只是 mock、为何需要复核、下一步可采取什么安全行动。

## 范围取舍

本测试版包含：

- 图片类型、空文件、过小文件与大小上限校验；
- 可替换 predictor 接口和确定性 mock fallback；
- 病害类别、风险级别、知识字段与免责声明合同；
- health 与 predict API 适配器；
- 正向、负向、边界和 provider 失败测试。

本测试版不包含：

- 真实病害模型、训练权重或准确率；
- 医疗/农技诊断结论；
- 真实采购定价或食品安全合规判断；
- 前端源码、生产部署、监控或用户数据。

## 验收条件

1. 同一输入在 mock 模式下返回稳定结果，并显式标记 `demo_mock`。
2. 非图片、空文件、过小文件和超过上限的文件返回可解释错误，不进入 predictor。
3. 真实 provider 未配置或失败时，响应必须包含 fallback 原因，不能静默伪装为模型输出。
4. provider 返回未知类别或越界置信度时立即拒绝。
5. 高风险类仍必须附带免责声明和人工/实验室复核提示。
6. 导入服务模块不得在仓库内创建输出目录或文件。

## 用户流程

```text
选择图片
  -> 输入校验
  -> 可用的真实 provider（未来）或显式 demo mock
  -> 预测合同校验
  -> 风险规则
  -> 知识字段与免责声明
  -> JSON 响应
```

## 失败路径

| 场景 | 产品处理 |
|---|---|
| 文件为空/过小 | 拒绝并提示重新上传清晰图片 |
| 类型或扩展名不允许 | 拒绝并列出支持格式 |
| 文件超过上限 | 读取上限后停止，避免无界内存占用 |
| 真实 provider 未配置 | 使用 demo mock，明确 `real_model_not_configured` |
| provider 异常 | 使用 demo mock，明确 `real_model_failed` |
| provider 合同不合法 | 失败关闭，不返回伪造成功结果 |
