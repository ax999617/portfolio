# 河南文化图像识别项目：算法重构与保守验证报告

## 1. 报告结论

本项目不再以“重新训练一个三分类模型并展示单一准确率”为主要目标，而是定位为一个可审计、可恢复、资源受限条件下仍保持诚实边界的视觉算法工程案例。模型训练只是完整流程的一部分；主要成果是数据就绪判定、稳定类别契约、防止数据泄漏、分阶段迁移学习、严格检查点和失败关闭机制。

完整三类原始图像已经找回，但当前仍是类别平铺归档，没有按拍摄来源划分 train/val/test。考虑到同一拍摄序列可能产生近重复图片，直接随机拆分会使验证结果偏乐观。因此本次只完成只读审计和算法重构，不运行真实训练，不生成新指标，也不修改原始数据。

旧模型权重和训练曲线继续作为历史原型证据展示，但不宣称为 v2 复现实验，也不用于证明当前算法的精度或节能收益。

## 3. 数据审计结论

### 3.1 完整原始目录

只读审计记录确认 `henan-complete-source` 包含以下三个非空类别目录：

1. `洛阳牡丹`
2. `郑州商代青铜器`
3. `信阳毛尖茶树`

该目录被判定为 `flat_source_archive`：类别材料完整，但没有 train/val/test 结构，因此 `source_complete=true`、`training_ready=false`。

### 3.2 不完整备份目录

`henan-incomplete-backup` 只保留“洛阳牡丹”和“郑州商代青铜器”，缺少“信阳毛尖茶树”。审计算法将其判定为不完整来源，并明确拒绝在缩减类别契约后继续训练。

### 3.3 为什么暂不自动拆分

图片文件名显示它们来自相机或移动设备拍摄序列。随机按单张图片拆分可能把同一对象、同一角度或连续帧分配到训练集和验证集，形成来源泄漏。仓库目前没有可靠的采集批次标注，算法不能仅凭文件名猜测拍摄组。因此保守策略是：

- 原始目录保持只读；
- 后续在独立副本中按拍摄来源人工分组；
- 同一对象或连续拍摄序列只能属于一个分区；
- 独立 test 集只在方案冻结后使用一次。

## 4. 历史方案的主要问题

### 4.1 模型和权重契约不一致

旧 `trained.py` 当前定义的是 ResNet-18 加 `Linear(512, 3)`，但 `trained.pth` 保存的分类头是 `512→1024→3`。旧推理脚本使用 `strict=False`，会忽略不匹配分类头并留下随机参数，因此不能把当前旧入口称为可复现推理。

### 4.2 类别索引存在冲突

训练、推理配置和旧 GUI 曾使用不同类别顺序。即使模型输出本身正确，标签解释也可能交换。v2 改为单一配置源，并把索引、英文 slug、中文展示名和原始目录名同时写入契约。

### 4.3 量化结论不可靠

旧量化脚本重新定义了另一套四层 CNN，再通过键名和形状过滤加载 ResNet 权重。体积变化主要来自模型结构改变，不能作为同一模型 INT8 量化收益。v2 暂停量化，只有浮点模型通过独立测试后才考虑带校准集的 PTQ 或 QAT。

### 4.4 训练过程不适合小数据和有限设备

旧流程从零训练完整 ResNet-18，缺少固定类别契约、冻结阶段、AMP、早停、最佳检查点和可靠恢复。对小型数据集而言，这种路线计算成本更高，且验证稳定性较差。

## 5. v2 算法设计

### 5.1 数据就绪状态机

新增 `audit_dataset.py`，只读检查目录结构、候选图片可解码性，并在已分区副本中读取必要的候选文件字节完成重复检测；它不下载模型、不训练、不写源目录。它区分以下状态：

1. `missing`：数据根不存在；
2. `flat_source_archive + source_complete=false`：原始归档缺类、多类或空类；
3. `flat_source_archive + source_complete=true`：原始类别完整，但尚未分区；
4. `prepared_splits + training_ready=false`：已有分区，但类别、空目录或重复检查失败；
5. `prepared_splits + training_ready=true`：显式 train/val 契约通过，可以进入训练阶段。

这种设计把“数据存在”和“可以训练”分开，避免看到三个文件夹就直接启动模型。

### 5.2 唯一类别契约

配置中固定以下模型索引：

```text
0 -> luoyang_peony             -> 洛阳牡丹
1 -> zhengzhou_bronze_artifact -> 郑州商代青铜器
2 -> xinyang_maojian_tea_plant -> 信阳毛尖茶树
```

训练数据使用 canonical slug；原始归档使用中文目录名。二者通过配置显式映射，避免依赖 `ImageFolder` 默认字典序。

### 5.3 防泄漏算法

对于准备好的 train/val/test 副本，代码先按文件大小分组，再仅对可能重复的候选文件计算分块 SHA-256。相同内容跨分区或跨类别时立即失败。这种两阶段检查减少了不必要的哈希读取。

该算法只保证发现字节完全一致的重复文件，不能发现重新裁剪、缩放或编码后的近重复；因此来源分组仍是前置要求。

### 5.4 资源感知训练

训练骨干改为固定权重枚举 `MobileNet_V3_Small_Weights.IMAGENET1K_V1`，输入尺寸为 192×192。默认只训练分类头，末端特征块微调关闭。只有分类头基线明确欠拟合时，才启用最后若干块，并为骨干设置更小学习率。

其他资源控制包括：

- CUDA 可用时启用 `torch.amp`，CPU/MPS 自动关闭；
- 冻结层的 BatchNorm 保持评估状态，防止统计量漂移；
- 使用验证损失调度和早停，减少无效 epoch；
- 已有实验目录默认拒绝覆盖；
- `last.pt` 保存完整运行状态，避免中断后从头计算；
- `best.pt` 只用于最终评估和推理。

192×192 相比 224×224 的输入像素面积理论上减少约 26.5%，但实际耗时和能耗必须在目标设备上实测，本报告不把该比例表述为真实节能结果。

### 5.5 严格检查点

v2 检查点同时保存模型参数和语义契约，包括：模型架构、权重枚举、类别索引、中文展示名、预处理、配置指纹、训练阶段、优化器、调度器、AMP scaler、早停状态和随机数状态。

恢复时既执行 `strict=True` 参数加载，也验证类别、预处理和配置指纹。任何冲突都会停止，而不是回退到随机模型。

## 7. 已完成的代码验证

验证只使用临时合成图片和随机张量，不读取真实数据进行训练。覆盖范围包括：

- 非字典序类别映射；
- 完整、缺类和平铺来源的数据审计状态；
- 损坏图片在平铺来源和已分区副本中的失败关闭；
- train/val 类别契约与字节级重复拒绝；
- 冻结骨干和 BatchNorm 稳定性；
- 分类头训练与可选末段微调；
- 严格检查点往返、损坏和语义不匹配失败；
- 双阶段合成训练、最佳/最后检查点和断点恢复；
- 中文及空格路径。

这些测试证明的是算法实现和失败边界，不代表真实数据上的模型效果。

本地验证环境为 Python 3.10.6、PyTorch 2.11.0 CPU、Torchvision 0.26.0。语法编译和全部离线测试均以退出码 0 完成；对完整真实目录执行 `--require-training-ready` 得到预期退出码 3，证明审计能识别“来源完整但尚未分区”，并在模型下载或训练前停止。

## 8. 后续执行顺序

1. 保持 `henan-complete-source` 只读；
2. 在独立位置建立 provenance-preserving 数据副本；
3. 人工确认拍摄对象和连续拍摄序列的分组；
4. 冻结分区后先运行 `audit_dataset.py --require-training-ready`；
5. 在硬件允许时只训练分类头基线；
6. 只有验证证据支持时才进行末段微调；
7. 最终只在独立 test 集评估一次；
8. 浮点模型通过后再单独评估部署和量化方案。

这一路线让项目即使暂不重新训练，也能清楚展示算法判断、工程约束和可验证性，而不是依赖无法复现的旧准确率。
