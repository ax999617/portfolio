# ComfyUI 招聘公开安全门禁 - test v1

## 审计结论

现有目录是本地历史工作流的混合归档，不适合直接作为招聘推荐入口。静态审查发现部分 workflow 文本和一张示例 PNG 的内嵌 prompt/workflow 元数据含成人或幼态敏感语义；即使可见图片不露骨，元数据仍可被下载者提取。

本测试版因此采取“先隔离、后重建”策略：不修改原文件、不复制风险 prompt、不生成新图片，也不把候选输出写成确定结果。

## 公开门禁

一个 AIGC 案例只有同时满足以下条件，才可进入招聘 README：

1. **需求清楚**：说明用户任务、输入、期望输出与不可接受结果。
2. **依赖可复现**：记录 ComfyUI 版本、custom node 名称与 commit、模型/LoRA 名称和许可。
3. **文本安全**：检查 workflow JSON 的 prompt、节点标题、模型名和备注，不含成人、仇恨或其他不适合岗位展示的语义。
4. **图片安全**：目视检查输出，并删除 PNG/JPEG 中的 prompt、workflow、路径和个人信息元数据后重新检查。
5. **来源明确**：记录 seed、输入来源和输出对应关系；无法确认的图片只标记为候选，不作为成果证据。
6. **失败可解释**：列出模型缺失、节点版本不兼容、角色漂移、姿势偏差、局部重绘边界和显存不足等失败路径。
7. **许可可说明**：无法确认模型、LoRA、节点或输入素材许可时，默认不公开。

## 求职案例结构

后续全新安全案例应按以下结构建立独立 `*_test_v2` 目录，而不是从混合归档直接复制：

```text
safe_case_test_v2/
|-- README_test_v2.md
|-- workflow_test_v2.json
|-- dependencies_test_v2.md
|-- inputs/README_test_v2.md
`-- outputs/README_test_v2.md
```

README 应回答：解决什么任务、为何选择这些节点、参数如何影响结果、如何验证、失败时如何排查、哪些内容没有被证明。
